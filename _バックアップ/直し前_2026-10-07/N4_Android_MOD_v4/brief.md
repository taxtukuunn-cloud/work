## 構成（1本の合計7,000字以上。セリフ,と説明,の本文だけで数える）
ファイルは3つの部分に分け、**区切りの行 `##PLAY` と `##END` を入れる**（ゲームには入らない印）。
1. **導入（`##PLAY` の前）：400字程度（300〜600字）**。冒頭行は画像行。どう負けたか（経路）、なぜこの責めなのか、どこへ連れて行かれたか。
2. **プレイ描写（`##PLAY` と `##END` の間）：6,000字以上（目標6,500〜7,500字）**。途切れさせず一連のシーンで。責め手の責め中のセリフ、主人公の喘ぎ声、快楽に対する心理描写、体や神経の反応、道具の動き（センサーの冷たさ、数値の読み上げ、アームの関節音、プローブの角度、拡張器の開く幅、吸引カップ、電極の痺れ、指の本数と角度、ローション）を細かく書く。**その責め手の得意技を主役にする**。絶頂は2〜4回（各絶頂の前に `射精` 行を置いてよい。触れずに達するなら置かない）。途中で後日談に飛ばない。
3. **結び（`##END` の後）：600字以内**。責め手の締めのセリフと、その後の短い余韻。
- 弱点付与・GAME OVER・BGMは別処理なので書かない。
- 文章の質：五感（白い照明、機械の駆動音、消毒液の匂い、計測台の冷たさ、濡れた音、モニターの波形）、比喩、緩急、責め手ごとの口調の個性。同じ責め手の4本は、場所・時刻・小道具・絶頂の区切り方・結末の印を変えて、読み比べて別物にする。

## 書式（厳守。ゲームのスクリプトとしてそのまま読み込まれる）
1行に1コマンド。使ってよい行は次だけ：
```
画像,#Android/Android_lose_<経路>_<責め手>.png,1
話者,%NX-00          （%検査ユニット %搾精ユニット %洗脳ユニット %中央制御ユニット も同様。責め手が喋る前に必ず入れる）
話者,相手プレイヤー    （主人公が喋る前に入れる）
セリフ,本文
説明,本文            （地の文・情景・心の動き）
フラッシュ,ピンク
射精
ウェイト,1
##PLAY
##END
```
- **本文に半角カンマ「,」を絶対に使わない**（全角「、」を使う）。
- 本文に `$ % & # { } < > ;` を使わない。半角の `!` `?` も避け、全角「！」「？」を使う。ハートや音符などの記号は使わない。半角の ( ) も使わず全角（）。改行したい時だけ `\n` を使ってよい（1行2〜3文まで）。
- 1行の本文は長くても120字程度。セリフは「」を付けない。
- 冒頭行は必ず `画像,#Android/Android_lose_<経路>_<責め手>.png,1`。ほかの画像ファイル名は使わない。
- 空行・コメント・見出し・`@` 行は書かない。`##PLAY` `##END` はそれぞれ1回だけ。

## 経路（どう負けたか）の軸
- **btl（戦闘負け）**：計測に耐えきれず、データ収集率が満了して崩れる。その責め手の流儀で堕とされる。
- **onani（オナニー負け）**：戦闘中、待機中のアンドロイドの前で我慢できずにその責め手の得意技を真似た自慰を始めてしまい、**その行為がすべてログに記録される**。「記録された」「見られていた」「再生される」が軸。**プレイ描写の最初は、下の「オナニーの内容」の自慰（ペニスは使わない）から始め、途中で責め手が引き取る。**
- **inochi（命乞い負け）**：追い詰めた時、相手が「停止コードを教える」などと持ちかけ、手を止めてしまう。それは罠で、情けを「協力の承認」と記録され、自分から実験に協力させられる（「協力、感謝します」「あなたが自分で承認しました」）。
- **onedari（おねだり負け）**：自分の口で「データを取ってください」と請い、どこをどう責めてほしいか具体的に言わされる。それが記録され、日課・定期検査になる。

## オナニーの内容（onani ルートの冒頭。ペニスは使わない）
- NX-00（脳波同期）：こめかみに指を当て、同期された時の信号を頭の中で再生する。手を使わずに腰が浮き、触れずに達しそうになる
- 検査ユニット（乳首スキャン）：自分の乳首をつまんで転がし、言われた感度の数値を小声で読み上げながら続ける
- 搾精ユニット（吸引搾精）：電極パッドの痺れを思い出し、下腹と会陰を指で小刻みに押して、吸い上げられる感覚を体の奥で再現しようとする
- 洗脳ユニット（音声波形）：手を使わない。耳に残った反復音声を自分で小声で繰り返し、言葉だけで体を震わせる
- 中央制御ユニット（高速ピストン）：ローションで濡らした指で後ろを一本ずつほぐし、ピストンの一定のリズムを真似て指を動かす
