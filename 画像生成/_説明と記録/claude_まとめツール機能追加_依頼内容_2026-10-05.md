# まとめツールへの機能追加：Claude Code への依頼書（2026-10-05・前提知識つき）

PC の Claude Code にそのまま渡すための依頼書。チャットで決めたことと、これまでのメモの要点を1本にまとめた。
Claude Code はプロジェクトのメモを自動では読まないので、必要な前提は4章に書いてある。

- 1〜3章：ねらいと、必ず守ること
- 4章：今の仕組み（前提知識）
- 5章：作る前に調べて報告すること
- 6章：作るもの
- 7〜9章：判定の基準、確かめ方、終わったらやること

**数字や設定値はメモを書いた時点のもの。実際の値は、PC のファイルと下見で必ず確かめること。**

---

## 1. ねらい

構図の元絵の「採用 → 奥行き → 人物の範囲 → 構図の登録 → 確認撮影」を、ユーザーが自分で画面を見ながらできるようにする。今は、一覧画像をチャットに貼って Claude が判定し、csv を手で書いている。

あわせて次の2つを入れる。

- 相手が複数いる場面で、相手ごとに範囲と文を分ける（今後、相手が複数の MOD を増やす予定がある）。
- 相手の種類（男の娘・女性・NH・翼や尻尾のある相手）に合う下書きだけを当てる。

追加先は今ある「まとめツール」。別の道具は作らず、タブを足す。

## 2. 必ず守ること

### 2-1. 触ってはいけないもの
1. プロジェクトの削除・権限の変更はしない。
2. ゲーム本体のフォルダ（`D:\GAME\SuccubusDuel本体\RJ01149693\SuccubusDuel_sub\サキュバスデュエル`）は、このプロジェクトで作ったファイル以外を更新しない。
3. 本プロジェクトで作ったファイル以外は書き換えない。
4. **年齢に関わる設定は変えない。画面から変えられる項目にも入れない。**
   - 対象：`model.json` の `hero_face`（`age_face`・`build`・`skin`・`skin_neg` など）、`scene_safety`、`gen.py` の `ADULT_POS`・`ADULT_NEG`・`ADULT_BODY_NEG`・`AGE_NEG`。
5. `prompts\*.json` を一括で書き換えない。今は、撮るときに `gen.py` が言い換える作り。相手ごとの文（6章 B6）の持ち方は、案を出してユーザーに確認してから決める。

### 2-2. 撮影が動いている間はしないこと
- `gen.py`・`make_region_masks.py`・`model.json` の変更（`gen.py` は MOD ごとに起動し直すので、途中から選び方が変わる）
- まとめツールの再起動
- 奥行きづくり・範囲づくり・確認撮影など、グラフィックボードを使う処理

### 2-3. 変更のしかた
7. 書き換える前に必ず控えを残す（`_控え\` に `〜前.py`・`〜前.json` など。今までの名前の付け方に合わせる）。
8. `model.json` は3章の決まりで控えを取る。
9. 別の作業が同じ日にファイルを変えていることがある。毎回 PC の最新版を読み、その上に変更を足す。
10. **選び方の規則を変えたら、反映の前に全 MOD の下見を回す**（`下見_全MOD.bat`＝`gen.py all all --preview`。約3分）。次を数えて報告する。
    - 組み立て失敗の数
    - 本文と下書きの姿勢の食い違い
    - 1つの MOD の中での下書きの重複
    - 下書きなしの場面
    - 下書きの割り当てが動いた場面（一覧つき）
11. 相手が1人の場面は、変更の前と後で下見の結果が同じになること（意図して変える場合は、その一覧を先に出す）。
12. 割り当てが動いた場面を撮り直すかどうかは、ユーザーが決める（`割り当てが変わった絵の撮り直し.bat`、`撮った絵の下書き一覧.py`）。
13. 今ある bat と処理は、今までどおり動くこと。
14. バッチで撮らない行は、消さずに `rem` で残し、行末に理由を書く。

### 2-4. ファイルの書き方
- 日本語を含む `.bat` は Shift-JIS（cp932）・CRLF・`chcp` なし。
- `gen.py` は CRLF。README は UTF-8。
- ComfyUI 付属の Python はスクリプトのフォルダを読み込み先に入れない。必要なら読み込みの前に `sys.path.insert(0, HERE)`。

### 2-5. ユーザーは csv を開けない（ユーザー決定）
- **csv は道具の中だけで使う。ユーザーに csv を開かせない・手で書かせない。**
- csv で持つ表は、すべてまとめツールの画面で「見る・書く・直す」ができるようにする。対象：`_採用.csv`、`_人物の範囲.csv`、`_元の名前.csv`、`_奥行き点検.csv`、`構図名_項目対応.csv`、`構図名_語の一覧.csv`、下見の結果（`下見_全場面.csv`・`下見_MOD別.csv`）、撮り直しの対象一覧 など。
- 画面の表は、並べ替えと絞り込み（MOD・構図名・印の種類など）ができるようにする。絵に関わる表は、行ごとに小さい絵を出す。
- 報告や一覧をユーザーに見せるときは、画面か、名前を書き込んだ一覧画像か、文章（md・txt）で出す。「csv を見てください」とは言わない。
- 説明書（`使い方.txt`）にも、csv を開く手順は書かない。

### 2-6. そのほか
- 個人利用のみ。画像・LoRA・MOD は配布しない。
- 説明や画面の文は、専門用語を避けたやさしい日本語で書く。

## 3. `model.json` の控えの決まり

- 書き換える直前に必ず控えを取る。名前は `_控え\model_<日時>_<変更内容>.json`（例：`model_20261005_1830_構図hj_stand_side登録前.json`）。
- 控えが取れなかったら書き換えない。中止して画面に知らせる。
- 控えは自動で消さない。
- 変更内容（どの項目がどう変わるか）を先に画面に出し、確認を押してから反映する。
- 控えの一覧から選んで、その時点に戻せるボタンを付ける。戻すときも、戻す前の状態を控えに取る。
- いつ・何を・どの控えから変えたかを、記録ファイルに1行ずつ書く。
- 撮影中は書き込みのボタンを押せないようにする。
- 画面から書き換えてよいのは `pose_control` の中の、構図の登録に関わる項目だけ（2-1 の4 の項目は対象外）。

### 4-2. 元絵が下書きになるまで

### 4-3. 人物の範囲の仕組み

- 顔を見つける（face_yolov8m）→ 顔の周りを CLIP で男女判定 → 一番男らしい顔＝主人公（青）、一番女らしい顔＝相手（赤）。
- 範囲は顔ごとの楕円（髪の上〜胸）。重なる所は近い顔へ。14px ぼかし。
- 主人公の顔が見つからない絵は、相手の頭だけの楕円。
- `_人物の範囲.csv` の「直す」欄に `入れ替え`／`主人公なし`／`使わない` と書いて再実行すると反映される。
- **色は主人公と相手の2色だけ。相手どうしは区別していない。**
- **手で範囲を指定する仕組みは無い。** 主人公が背中向きの絵、顔が相手のすぐ下にある絵、顔がマスクや髪で隠れた絵は、正しく付かない。
- 人物の切り分け（yolov8x-seg）は、重なった2人を1人にまとめるので使っていない。
- 撮るとき（`gen.py`）：範囲の画像があれば、主人公の範囲には主人公の文（`pose_control.region.hero_text`）、相手の範囲には場面の文から主人公の見た目を抜いた文を渡す。強さ 0.8。主人公目線の下書きは相手だけ。
- `strip_partner_hair`：主人公と相手の両方に範囲があるとき、画面全体の文から相手の髪色を抜く。**相手が2人以上の場面では抜かない**（2人が同じ髪色になる・主人公の紺が相手に移るため）。
- 下書きの優先：同じ構図の中では「主人公の範囲あり ＞ 相手だけ ＞ なし」（`resolve_ref`）。範囲が無い下書きは、同じ組に範囲つきがあると選ばれない。
- 女装の場面は、主人公の範囲つきの下書きに限っている。

### 4-4. 下書きの選び方（`model.json` の `pose_control`）

| 項目 | 中身 |
|---|---|
| `ref_tags` | 構図ごとの視点タグ（pov・from side など） |
| `ref_role` | 構図ごとの役の文（誰がどこにいるか） |
| `ref_sets` | 組。各行の `when`（主人公の姿勢の条件）に当たった構図が候補。`not` で除外 |
| `by_pose` | 技の判定。場面の文の語から、どの組に当てるかを決める |
| `lora_alt`・`lora_alt_force` | 構図 LoRA が当たる場面を、元絵の組に置き換える |
| `ref_for_3d` | 3D の下書きを、似た元絵の組に置き換える |
| `fallback`・`fallback_not` | どれにも当たらない場面の姿勢別の組 |
| `ref_exclude` | 使わない下書き |
| `ref_extra` | 後から足した構図。最初の1枚には選ばず、同じ MOD で重なったときの替えにだけ使う |
| `posture_rx`・`ref_posture`・`posture_filter`・`posture_dedup_any` | 本文の姿勢と合う構図だけを最初の候補にする |
| `dedup_in_mod` | 1つの MOD の中で同じ下書きを使わない（`plan_refs`） |
| `pov_fix` | 主人公目線の下書きが当たった場面は、主人公の顔・髪の語を外す |
| `ref_control` | 効かせ方（union depth 0.6・end 0.5・`region_strength` 0.8） |
| `landscape_on` | 横長で撮る構図 |

- 構図の中の何枚目を使うかは、画像名から決まる（撮り直しても同じ）。
- 撮影のシードも画像名から決まる。条件が同じ場面は同じ絵になる。別の絵にするには `--random`。

### 4-5. 元絵から引っ張られるもの

奥行きに残るのは形だけ。色・絵柄・顔は移らない。

- **移る**：体の位置とカメラの向き、体格と頭身、胸のふくらみ、服の輪郭、髪の輪郭、翼・尻尾・角・触手、人数、手の位置、頭などの切れ方、椅子や窓枠などの形、小物（眼鏡・鈴・ビーズ・髪飾り）、平塗りの絵の線。
- **ほぼ移らない**：擬音や小さな文字、口元の薄いマスク。
- 例：受け側が筋肉質の元絵 → 主人公が筋肉質。受け側の位置に乳房 → 主人公に乳房。元絵の男が服を着ている → 主人公が服を着る。元絵が1人だけ → 相手が消える。

## 6. 作るもの

### 段階A：画面の追加（撮影中に書いてよい。反映と動作確認は撮影が終わってから）

`ui.html` と `app.py` だけを変える。

**A1. 採用の画面（見本つき）**
- `_候補` の絵を並べる。
- 登録済みの構図を、見本の絵つきで並べる。ユーザーは「これと同じ形」を選ぶ。
- 選んだ結果を `_採用.csv` に書く。今の csv と同じ形にして、`adopt_ref.py` がそのまま読めるようにする。
- 切り抜き・左右反転も画面で指定できるようにする。
- 判定の基準（7章）を画面に常に出しておく。

**A2. 「新しい構図」に分ける**
- どの見本にも合わない絵に印を付け、別の一覧に出す。ここに入った絵は登録をせず、後でまとめて決める。
- 新しい構図名で取り込んでも、登録するまでは撮影に使われない（今の作りのまま）。

**A3. 範囲の確認画面**
- 青（主人公）と赤（相手）を絵に重ねて表示する。
- `入れ替え`・`主人公なし`・`使わない` をボタンで付け、`_人物の範囲.csv` の「直す」欄に書く。

**A4. 当たり具合の一覧**
- 下見と `--pose-report` の結果を画面に出す。構図ごとに、どの MOD のどの場面に何枚当たったかを見られるようにする。
- 2-3 の10 の数（組み立て失敗・食い違い・重複・下書きなし・動いた場面）も出す。

**A5. 判定のメモ欄**
- 採用・見送り・外した理由を1行で残せる欄を付ける。

**A6. 項目をつなげて構図名（ファイル名）にする**
- ねらい：ファイル名を見ただけで、どの構図かが分かるようにする。細かい技の種類はユーザーが選ぶ。名前と白黒の下書きを Claude に見せて、当てる場面の種類を判断させる使い方もする。
- 採用の画面で、項目を選択肢から選ぶと、名前が自動で組み立てられる。組み立てた名前は、その場で画面に出す。
- **つなげる順番**（決まった順。区切りは `_`）

| 順 | 項目 | 例（案。今ある名前の語に合わせて調整すること） |
|---|---|---|
| 1 | 相手の人数（2人以上のときだけ） | two・three |
| 2 | 技 | kiss・hj（手）・foot（足）・nipple（乳首）・ear（耳）・whisper（ささやき）・finger（指・前立腺）・peg（ペニバン・逆アナル）・urethra（尿道）・chastity（貞操帯）・armpit（脇）・thigh（太もも）・chest（胸に顔）・drain（精気を吸う）・bloodsuck（吸血）・bound（拘束）・straddle（またがる）・hug（抱く） |
| 3 | 主人公の姿勢 | lie（寝る）・prone（うつ伏せ）・sit（座る）・stand（立つ）・bent（前かがみ）・fours（四つんばい）・kneel（ひざまずく）・hang（吊り） |

- 例：`hj_stand_side`（手・立つ・横から）、`peg_bent_side_back_nipple`（ペニバン・前かがみ・横から・後ろから・乳首も）、`two_ear_sit_front`（相手2人・耳・座る・前から）。
- 画面では、名前の横に日本語の読み（「手・立つ・横から」）を必ず出す。一覧画像（B7）にも名前と日本語の読みを書く。
- **同じ項目の構図がすでにあるとき**：その構図の見本を出し、「同じ形なので足す」か「形が違うので別の構図にする」を選ぶ。別にするときは末尾に `b`・`c` を付ける（今ある `_b` の付け方に合わせる）。
- **今ある構図名は変えない。** 構図名は `model.json` の登録や、撮り済みの絵の記録、重複よけの計画の鍵になっているため。
  - 代わりに、今ある構図名と項目の対応表（`構図名_項目対応.csv`）を作る。画面と一覧画像では、古い名前にも日本語の読みを出す。
  - 対応表の最初の案は、名前と `ref_tags`・`ref_posture`・`ref_sets` から機械的に作り、分からない所は空欄にして、ユーザーが画面で埋める。
- **1枚ごとの項目（胸・付属物）は、構図名には入れない。** 同じ構図の中で絵ごとに違うため。B8 の表に持たせ、画面と一覧画像で名前の横に出す。
  - ファイル名の末尾にも付けたい場合は、道具が名前から構図名を読む部分（`adopt_ref.py`・`import_pose_ref.py`・`depth_from_ref.py`・`make_region_masks.py`・`gen.py` の `resolve_ref` など）への影響を調べ、案を出してユーザーに確認する。
- **名前は英字の短い語のままにする**（今までの名前と同じ形。日本語のファイル名にはしない）。
- **選択肢には必ず日本語訳を並べて出す**（ユーザー決定）。表示は「日本語（英字）」の形。例：「手（hj）」「立つ（stand）」「横から（side）」。選ぶときは日本語で読め、名前には英字が入る。
  - 英字の語と日本語訳の対応は1つの表（`構図名_語の一覧.csv`）にまとめ、画面・一覧画像・対応表がすべてこの表を使う。語を足すときは、画面からこの表に足す。
  - 画面には、語の一覧（英字と日本語訳の早見表）をいつでも開けるようにする。
- 選んだ項目は、そのまま B2 の登録（視点・姿勢・技の組）と B8（相手の種類）の入力に使う。同じことを2回選ばせない。

**A7. MOD ごとの下書きの割り当てを見る画面**
- ねらい：各 MOD のどの場面に、どの構図のどの下書きが当たっているかを、絵つきで見られるようにする（ユーザー決定）。
- **見方は2通り**
  - MOD から見る：MOD を選ぶと、その MOD の場面が順に並ぶ。
  - 構図から見る：構図（または下書き1枚）を選ぶと、それが当たっている場面が MOD をまたいで並ぶ（A4 と同じ表を、こちらからも開けるようにする）。
- **1場面ごとに出すもの**
  - 画像の名前と、場面の種類（攻撃・敗北・立ち絵 など）
  - 当たった構図名と日本語の読み（A6）、下書きの名前
  - 絵を横に並べる：元絵／白黒の下書き／範囲（青と赤を重ねたもの）／撮った絵（あれば）。押すと大きく見られる。
  - 本文から読んだ主人公の姿勢と、下書きの姿勢
  - 選ばれた理由（どの技の判定・どの組から来たか、替え〈`ref_extra`〉か、構図 LoRA からの置き換えか）
  - 相手の種類（男の娘・女性・NH、翼や尻尾）と、下書きの項目（胸・付属物）（B8 ができてから）
- **その場面のシチュエーションも出す**（ユーザー決定。下書きが場面に合っているかを、絵と文を見比べて判断するため）
  - 相手の名前と、技の名前（カード名・攻撃名）
  - 技の種類：得意技か、累積スタックの技か。累積スタックなら、何段階めの絵か（主人公用・味方モンスター用の別も）
  - 攻撃時のセリフ（その絵と一緒に出るもの）
  - 敗北シナリオの絵なら、その絵が出る所の前後の本文（数行。押すと続きが読める）
  - 回想バトルやオナニー場面など、場面の種類
  - 絵の指示（`prompts\<MOD>.json` のその場面の文）。英語のままなので、`gen.py` がそこから読み取った内容を日本語で並べて出す：技の判定、主人公の姿勢、視点、相手の種類、触れる・触れないの別、女装かどうか
  - キャラクターの設定の要点（得意技、身長・スリーサイズ、男の娘・NH などの別）。元は MOD の設定か、`画像生成` 側にある情報から読む
  - **どこから読むかを先に調べて報告する**：技の名前・セリフ・本文が、MOD のどのファイルにどんな形で入っているか。画像の名前と、セリフ・本文の位置をどう結び付けられるか。MOD によって形が違う（N1〜N15、N16〜N60、N61〜N105、N106〜N157 で作りが違う）ので、読めない MOD は「読めません」と出し、どの MOD が読めないかを一覧で報告する。
  - この画面は読むだけ。セリフ・本文・絵の指示は書き換えない。
  - 文と下書きが合わないと思ったときのために、「本文に下書きを合わせる（下書きを替える・外す）」か「後で本文を直す対象としてメモする」を選べるようにする。メモは一覧にためて、文章で出せるようにする（本文の直しは別の作業）。
- **印を付ける**（色か記号で一目で分かるように）
  - 下書きなし
  - 本文と下書きの姿勢の食い違い
  - 同じ MOD の中での重複
  - 今の割り当てと、撮ったときの下書きが違う（撮り直しの対象）
  - 相手の種類と下書きが合っていない（B8 ができてから）
  - 範囲が無い・範囲が主人公なし
- **絞り込みと並べ替え**：MOD、構図名、技、印の種類、「印のある場面だけ」。
- **MOD ごとのまとめ**：場面の数、下書きありの数、印の種類ごとの数を、MOD の一覧に出す。数の多い MOD から順に並べられるようにする。
- **元になる情報**：今の割り当ては下見（`gen.py <MOD> all --preview`、全体は `下見_全MOD.bat`）の結果を読む。撮ったときの下書きは `撮った絵の下書き一覧.py` と同じ読み方で、撮った絵に入っている記録から読む。
  - 下見がいつのものかを画面に出す。`model.json` や下書きが下見より新しいときは「下見が古い」と出し、ボタンで下見をやり直せるようにする（撮影中は押せない）。
- **この画面からできる操作**（今ある道具を呼ぶだけ）
  - その下書きを外す（`下書きを外す` と同じ。外す前に、ほかにどの場面が影響を受けるかを出す）
  - その場面を撮り直しに回す
  - その下書きの範囲の確認画面（A3）・点検画面（B7）へ移る
- **場面ごとに下書きを手で指定する機能**は、今の作りに無い。入れる場合の案（持ち方、重複よけ・姿勢合わせとの優先の順番）を出して、ユーザーに確認してから作る。
- 絵の数が多い（全体で約3,000場面）ので、小さい絵は作り置きして、画面が重くならないようにする。

### 段階B：撮影が終わってから

**B1. 手での範囲指定**
- 絵の上をドラッグして囲む（四角か楕円）。拡大できるようにする。
- 囲んだ形を、主人公・相手1・相手2 の範囲の画像として保存する。
- 手で指定した範囲は、顔の検出の結果より優先する。
- ねらい：主人公が背中向きの絵、顔が相手のすぐ下にある絵、顔が隠れた絵、相手が複数の絵を、捨てずに使えるようにする。

**B2. 構図の登録（`model.json` への書き込み）**
- 視点・姿勢・技の組・相手の種類（B8 の項目）を選択肢から選ぶ。
- 役の文は、選んだ内容から決まり文句を自動で作り、必要なら手で直せるようにする。
- 新しく足す構図を、最初の候補にするか、重なったときの替え専用（`ref_extra`）にするかを選べるようにする。既定は替え専用（撮り済みの絵への影響が小さいため）。
- 合う組がまだ無い構図は、画面からは登録しない。「新しい構図」の一覧に残し、条件づくりは Claude Code が全 MOD の場面の文と照らして行い、下見の結果を報告する。
- 条件づくりの注意（過去の失敗）：背景の語だけで当たる（「two chairs」で椅子の構図、「upside-down」のグラスで逆さ吊り、「dust suspended」で吊り）。主人公の体勢を書いた語にだけ当たるようにする。語を広げすぎると関係ない場面まで動く。
- 書き込みは3章の決まりに従う。書き込みの後は下見を回す。

**B3. 確認撮影のボタン**
- 選んだ下書きで数枚撮り、その場で見られるようにする（今ある `--control-sample`・`--control-id` を呼ぶ）。
- 見るところを画面に出す：役が逆でないか、主人公が筋肉質・大柄でないか、主人公が女性の体になっていないか、頭が切れていないか、相手の服や翼が主人公に移っていないか、人物が幼く見えないか。

**B4. 似た構図を自動で上に出す**
- 新しい絵の奥行き画像と、登録済みの奥行き画像の形の近さを比べ、近い順に3つほど候補を出す。
- **先に測る**：取り込み済みの元絵で、1枚を抜いて残りから候補を出し、正しい構図名が上位3つに入る割合を出して報告する。割合が低ければ、比べ方を変えるか、この機能を見送る。

**B5. 相手の種類の自動入力（WD14 Tagger）**
- 元の絵にかけて、翼・尻尾・角・触手・胸の大きさなどを自動で拾い、選択肢にあらかじめ入れる。ユーザーが画面で確認して直す。
- **先に測る**：取り込み済みの元絵にかけ、登録済みの内容と項目ごとに何割合うかを報告する。
- 任せるのは B8 の項目の下書きだけ。どちらが主人公か、敵上位か、大人の体つきかは任せない。

**B6. 相手ごとの分割（相手が複数の場面）**
- 範囲を相手ごとに分ける：`make_region_masks.py` が `_partner1.png`・`_partner2.png` を出す。
- 当て方の既定は「画面の左から順に相手1・相手2」。違う絵だけ画面で入れ替える。
- 場面の文も相手ごとに分けて持てるようにする（「相手1の見た目」「相手2の見た目」）。持ち方は案を出してユーザーに確認する（2-1 の5）。`gen.py` は範囲ごとに別の文を渡す。
- 相手が1人の場面は今と同じ結果になること（2-3 の11）。
- **まず Twins の1場面だけで試す**。髪色・服が混ざらないか、密着した構図でどうかを報告してから広げる。
- 既存の Twins（12場面）・Heels boss（4場面）の文の書き直しは、試しの結果を見てから。

**B7. 奥行き（白黒の下書き）の自動点検**
- ねらい：全部を目で見なくて済むように、怪しい下書きにだけ印を付ける。
- **計算で検出する（毎回同じ結果になる）**
  - 頭や体が画面の端で切れている。
  - 大きな四角い枠（窓枠・黒い余白）が形として残っている。
- **Claude Code が奥行きの一覧を見て印を付ける**
  - 形が読めない（腕や脚がかたまりになっている、2人の体が分かれていない）。
  - 小物や線が形として残っている（眼鏡・鈴・ビーズ・髪飾り・修正の線など）。
  - 1人だけになっている。
  - 大きな翼・太い尻尾・蛇の胴・触手がある。
- **結果は必ず画像の名前つきで出す**（ユーザーが自分でも確かめられるようにする）
  - 表：`構図下書き\_奥行き点検.csv`（下書きの名前・元絵の名前・構図名・印の種類・検出の方法〈計算／目〉・メモ）。
  - 一覧画像：1枚ごとに下書きの名前を絵の下に書く。印の付いた絵だけを集めた一覧も作る。
  - まとめツールの画面：印の付いた絵を名前つきで並べ、「問題なし」「外す」「相手の種類を付ける」をボタンで選べるようにする。
- 印が無い絵が必ず大丈夫とは限らない（縮小して見るため、小さな崩れは拾えない）。最後は確認撮影で確かめる。
- 白黒からは判断しないこと：どちらが主人公か、筋肉質か、服の有無、技の種類。これらは元の絵を人が見て決める。
- WD14 Tagger は白黒の画像には使わない（元の絵にかける）。

**B8. 相手の種類で下書きを当て分ける（胸の大きさを含む）**
- ねらい：元絵の形（胸・翼・尻尾など）は奥行きに残り、生成した絵に出る。相手に合わない下書きを当てないようにする。
  - 胸の大きい下書きを男の娘に当てると、男の娘に乳房が付く。
  - 翼や尻尾のある下書きを人の相手に当てると、翼や尻尾が出る。
  - 逆に、平らな胸の下書きを胸の大きい女性に当てると胸が小さくなり、翼の無い下書きを翼のある相手に当てると翼が出にくい。
- **下書きごとに持たせる項目**（B2 の登録画面・B7 の点検画面で付ける。置き場所は `model.json` か別の表かを提案すること）
  - 胸：平ら／小さめ／あり／写らない
  - 体つき：細身／くびれと尻が強い
  - 付属物：なし／翼／尻尾／角／蛇の胴／触手／多い腕 など
  - 胸を使う構図か（挟む・顔をうずめる など）
- **場面の側の判定**：相手が男の娘か、女性か、NH・ふたなりか、翼や尻尾があるかは、場面の文から読む（5章の7）。
- **当て方の決まり**

| 相手 | 当てる下書き |
|---|---|
| 男の娘 | 胸が「平ら」「小さめ」「写らない」。胸を使う構図は当てない。体つきは細身を優先 |
| 女性 | 胸が「あり」「写らない」を優先 |
| NH・ふたなり | 胸が「あり」「写らない」を優先（設定上、胸がある） |
| 翼・尻尾などがある相手 | 同じ付属物のある下書きを優先。無ければ付属物なし |
| 人の相手 | 付属物なしだけ |

- 作りは、今ある姿勢合わせ（`posture_filter`）と同じ考え方にする：合わない下書きは最初の候補から外し、合う候補が1枚も無ければ外さない（下書きなしにはしない）。どの場面がそうなったかを一覧で報告する。
- これができたら、今 `ref_exclude` に入れてある翼・尻尾などの49枚を戻せるか確かめる。
- **先に数える**：当て分けた後に、候補が足りなくなる構図はどれか。足りない構図は元絵集めの対象として報告する。
- 重複よけと両立させる。候補が減って重複が増える構図を報告する。
- 女装の場面の制限（主人公の範囲つきの下書きに限る）とも両立させる。
- 撮り終えた MOD は選び方が変わる。撮り直す対象の場面を一覧で出す（撮り直すかどうかはユーザーが決める）。

## 7. 判定の基準（採用の画面に出しておく文）

**通す絵**
- 相手が画面の主役で、大人の体つき（顔ではなく体で見る）。
- 主人公が映らない目線の絵か、映っていても相手より小さいか同じくらい。
- 2人の体がはっきり分かれて見える。
- 主人公の顔が写っている（主人公目線の構図は除く）。
- 裸の場面用なら、主人公にあたる人物が裸。
- 長辺 800px 以上。

**外す絵**

- 受け側が筋肉質で大柄。受け側が女性の体に見える。男側が相手より大柄。
- 主人公の体が画面の真ん中を占める。主人公の頭が隠れる。
- 1人だけの絵。接写（主人公目線のキスだけは可）。体が絡んで読めない絵。
- 敵上位と逆の体勢。
- 250〜500px の小さい絵。

**主人公目線のキスを通す条件**
- 相手が大人の顔つき。見ている側の手が相手の顔を包んでいない。相手のほうから迫る形。

**幼さの見方の注意**
- 主人公目線や寄りの絵では、遠近で頭が大きく見える。頭の大きさだけで幼いと決めない。
- 真横からなど、カメラから同じ距離の絵で体が小さいものは外す。

**奥行きの点検で見ること**
- 2人の体が別々の形として読めるか。
- 窓枠・黒い余白・小物・線が形として残っていないか。
- 頭が切れていないか。
- 翼・尻尾・触手・大きな小物が無いか（あれば、相手の種類を付ける）。

**足りない元絵（メモの時点）**
- キス（主人公目線）、前立腺・指、貞操帯、座って胸に顔をうずめる、四つんばいを横から、尿道。
- 相手が2人：座って挟まれる、四つんばいを後ろと下から2人で、寝ている主人公に2〜3人。
- 立ったままのささやき、ソファで膝の上に向かい合ってまたがる、柱にもたれて座る主人公を立って膝で責める。
- 男の娘用：胸が平らな相手の下書き（B8 の数えた結果で対象を決める）。

- **説明書を作る**（ユーザー決定。下の「説明書の決まり」に従う）。

### 説明書の決まり

- **置き場所と開き方**：まとめツールの画面に「説明書」のボタンを付け、押すと画面の中で開く。ファイルを探して開く必要が無いようにする。中身は `まとめツール\説明書.html`（画面で見る用）。今ある `使い方.txt` にも同じ内容の要点を書き足す。
- **書き方**：専門用語を避けたやさしい日本語。1つの手順は1つの動作。「どのタブの、どのボタンを押すと、何が起きるか」の順で書く。csv を開く手順は書かない。
- **画面の絵を入れる**：手順ごとに、実際の画面の絵（どこを押すかに印を付けたもの）を入れる。画面の絵に成人向けの絵が写り込まないよう、見本の部分は白黒の下書きか、ぼかした絵にする。
- **入れる内容**
  1. 始め方と終わり方（`まとめツール.bat`、ComfyUI を先に起動すること、撮影中にしてはいけないこと）
  2. 全体の流れの図（元絵を入れる → 採用 → 奥行き → 範囲 → 登録 → 下見 → 確認撮影 → 撮影）
  3. 元絵を入れる場所と、絵の選び方（7章の判定の基準をそのまま載せる）
  4. 採用の画面：見本から選ぶ／項目を選んで名前を作る／切り抜き・左右反転／「新しい構図」に分ける
  5. 語の早見表（英字と日本語訳。画面の表と同じ内容）と、名前の読み方の例
  6. 奥行きの点検：印の意味と、「問題なし」「外す」「相手の種類を付ける」の選び方
  7. 範囲の確認：青と赤の意味、`入れ替え`・`主人公なし`・`使わない` の使い分け、手で囲むやり方
  8. 相手が複数のとき：相手1・相手2 の決まり方と入れ替え方
  9. 相手の種類（胸・翼・尻尾など）の付け方と、男の娘・女性・NH でどう当たるか
  10. 構図の登録：変更内容の確認のしかた、替え専用にするかどうか、登録できない構図（「新しい構図」）の扱い
  11. 下見の見方：食い違い・重複・下書きなし・動いた場面の意味と、数が増えたときにすること。MOD ごとの割り当ての画面（A7）の見方と、印の意味
  12. 確認撮影：見るところ（役が逆、筋肉質、頭が切れる、服や翼が移る、幼く見える）と、だめだったときの外し方
  13. 撮り直し：割り当てが動いた場面の一覧の見方と、撮り直すかどうかの決め方
  14. 控えから戻す：`model.json` を前の状態に戻す手順
  15. 困ったとき：よくある症状と対処（画面が開かない、ボタンが押せない〈撮影中〉、範囲が付かない、下書きが選ばれない、相手に翼や胸が出る、主人公が筋肉質になる など）
  16. してはいけないこと（2章の要点：撮影中の変更、年齢に関わる設定、ゲーム本体のファイル）
- **できていない機能は書かない**。後回しの機能（スマホ対応など）は「まだ使えません」と1行だけ書く。
- **機能を足したり変えたりしたら、同じ作業の中で説明書も直す。** 説明書と実際の画面が食い違ったままにしない。
- 説明書は、実機で手順どおりに操作して確かめてから渡す。
