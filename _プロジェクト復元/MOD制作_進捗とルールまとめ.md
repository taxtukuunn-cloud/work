## 1. 絶対条件（全MOD共通）
- 登場人物はすべて20歳以上。個人利用のみ。
- 責め手上位が絶対条件。主人公側は快楽攻撃を使わない。逆転なし。主人公は挿入しない。
- 主人公側のモンスターは男モンスターのみ。
- 相手キャラ（敵側）は常に責めオンリー。自慰・受け身・自爆にしない。
- 各キャラの攻撃は2種以上（マスターは3種）。負けたらそのキャラ専用の敗北シナリオ（各5,000字以上）。
- 攻撃時にセリフと画像を出す。BGMは本編のものを流用。画像はComfyUIで生成。
- **女装娘ルール（2026-09-23 決定。N16〜N30で導入）**：主人公側の男モンスターが女装化系の技・魔法を受けたら、その時点で即、破壊扱いになり、「女装娘」として主人公側（自分フィールド）に特殊召喚される。詳細は `claude/新MOD企画書_N16-N30_v3.md` 2章。
- **同時攻撃ルール（2026-09-23 決定。N16〜N30で導入）**：1つの技で2〜3か所を同時に責める【同時】技を使える。同じ部位どうしは組み合わせない（例外：乳首舐め＋乳首責めは左右で分ければ可）。【同時】技はゲージ+3。詳細は `claude/新MOD企画書_N16-N30_v3.md` 0〜1章。

### 3-1. 書式
- 1行目は `default`。改行コードはCRLF。
- **`if` の後は必ず `{ … }` で囲む**（1行だけでも省略しない。省略すると処理がそこで止まる）。**`else` は `}else{` を1行で書く。**
  - **「かつ」の条件も入れ子で書く**：`if,A` の次の行に `if,B` を続けて書かない。`if,A` → `{` → `if,B` → `{ … }` → `}` とする（N2で17か所見つけて直した。2026-09-23）。
- セリフ・説明の本文に半角カンマ禁止（全角「、」。どうしても半角カンマを出すなら `;`）。改行は `\n`。
- 本文に `$ % & # { } < >` を使わない（変数・タグとして解釈される）。`{変数}` は変数表示にだけ使う。
- `//` コメントは行を分ければ使えるが、カードtxtには基本書かない。

```

    &カード画像,#<コード>/<ファイル>.png

    最大HP設定,10000          ← マスターはLPとして表示

    タイプ設定,悪魔            ← 魔術師・戦士・ローグ・ハンター・植物・獣・爬虫類・アンデッド・悪魔・天使・妖精・スライム・昆虫・ドラゴン・機械・水棲・岩石／通常魔法・永続魔法・装備魔法・通常罠・永続罠
    性別設定,女                ← 男・女・その他
    レアリティ設定,UR          ← N・R・SR・UR
    攻撃エフェクト設定,&&セクシーエフェクト

```
- `@初期設定` はカード読み込みのたびに実行される。**ゲージのリセットなど、戦闘中の値をここで0にしない。**

### 3-3. 画像・音
- 画像は **`#<コード>/<ファイル>.png`**（ゲームの **Saveフォルダと同じ階層の `Picture` フォルダ** 基準）。
- `&&名前` は本編内蔵の素材だけ：`&&戦闘BGM` `&&敗北BGM` `&&キスエフェクト` `&&セクシーエフェクト` `&&斬るエフェクト` `&&怪しい光SE` `&&注ぐSE` など。自作の `&&〜` は存在しない。
- 画像ファイルが見つからないと、その行で処理が止まる可能性がある。ファイル名は必ずカードと一致させる（6章の install_images.bat を使う）。

### 3-4. セクション（呼ばれる場所）
- **全カード共通**：@戦闘・@戦闘後・@オナニー・@おねだり・@おねだり後・@命乞い・@敗北後・@終了時一言・@弱点攻撃・@瀕死時セリフ・@効果
  - 公式ドキュメントには、ほかに **@戦闘破壊・@効果破壊・@状態異常ダメージ破壊** もある（N11の分裂で @戦闘破壊 を使用。未検証）。
- **マスター（プレイヤー）専用**：@試合開始・@ターン開始・@ターン終了・@通常ドロー・@召喚宣言・@攻撃宣言・@ターン終了宣言 など。**モンスターでは呼ばれない。**
- モンスターの召喚時・ターン終了時の処理は **効果** で書く（3-7）。
- 街バトル用の受け口：使っている全セクションに `@戦闘_街バトル` → `イベント実行,戦闘` の形を置く（既存MODと同じ）。
- `@命乞い` には必ず `命乞い失敗` を入れる（ないとそのモンスターが不死身になる）。

### 3-5. 攻撃（`@戦闘`）
- **攻撃タイプはゲームにある名前だけ**：通常攻撃・おっぱい・パイズリ・ぱふぱふ・フェラ・手コキ・足コキ・脇コキ・ハグ・ふとももコキ・膝コキ・尻コキ・尻尾コキ・髪コキ・キス・スマタ・素股・魔法責め・触手・触手コキ・耳責め・乳首責め・強制自慰・パンチラ・息・本番。
- 自作の技名は **`技名表示,技名`** で画面に出す。
- **`攻撃タイプランダム変更` は `@戦闘` の先頭**に書く（`@攻撃宣言` ではない）。
- 攻撃時の順番：**`話者変更,自分` → `技名表示` → `画像表示` → 責め手のセリフ → `話者変更,相手` → 主人公の反応 → `話者変更,自分` → ゲージ加算・表示**。
  **`技名表示` の後に `話者変更` を入れると技名が消える。**
- おねだりの技固定（`攻撃タイプ固定`）で、別のカードがどの技にも当てはまらない場合がある → `@戦闘` の最後に「当てはまらなかった攻撃も+1」する処理を入れる（4章のテンプレに含む）。
- 主人公の反応は `話者変更,相手` の後にセリフ（受けたのが男モンスターならその声）。
- **段階のセリフの書き方（N6）**：`@戦闘` の頭で `$段階` を1〜4に決めてから `if,$段階,==,1` のように分けると、範囲の入れ子（`>=6` かつ `<12`）が要らず、if が平らになる。

### 3-6. 変数・ゲージ
- `$` `&` `%` はそのファイルの中だけ。`$$` はセーブされるグローバル変数（前回の敗北などの記録用）。`$$` は **`$$<コード>_名前`** のように頭に付けて本編と被らせない。
- **戦闘中のゲージは、敵マスターのカード変数 `自分プレイヤー.$ゲージ名` に持たせる**（`$$` では戦闘中に積み上がらなかった）。モンスター・魔法からも同じ書き方で増やす。マスター自身の `@試合開始` で `自分.$ゲージ名,=,0`。
- 表示は一度ローカル変数に写してから：`$表示用,=,自分プレイヤー.$淫紋度` → `説明,（淫紋度 {$表示用}／24）`。
- **ゲージは減らさない。** 24に達したら、攻撃時はその場で、それ以外はマスターのターン終了時に `とどめダメージ,相手プレイヤー,9999`。
  - **N2（Circle）は例外として未修正**：ゲージがマスターのローカル変数 `$キス度` で、ターン終了時に −1 される。実機で見てから直すか決める（`claude/N2_Circle_完成メモ.md`）。
- 状態異常付与：`状態異常付与,対象,状態異常名,ターン数`（効果の中では対象を `相手プレイヤー` にする）。使える状態異常：魅了・寸止め・発情・発情強・メロメロ・ぬるぬる・麻痺・攻撃不能・魔法使用不能・攻撃指示不能・洗脳・拘束・見惚れ・早漏化・弱点付与スキル など。
- **N13で導入（未検証）**：最後の責め手・技・敗北経路も `自分プレイヤー.$最後の責め手` `$最後の技` `$敗北経路` に持たせて全カードで共有し、どのカードの `@敗北後` が呼ばれても正しい話を流せるようにした（`$$<コード>_再生済` で二重再生を防止）。
  - N11も同じ方式。二重再生の防止は `$$` ではなく `自分プレイヤー.$再生済`（`@試合開始` で0に戻す）にした。
  - N6も同じ方式（`自分プレイヤー.$敗北再生済み`）。`@おねだり後` で `$敗北経路` を0に戻すのは `if,相手プレイヤー.HP,>,0` のときだけにして、おねだりの攻撃で負けた時に経路が消えないようにした（未検証）。

### 3-7. 効果（魔法・罠・モンスターの召喚時など）
- `効果設定,ID,種別,説明`（種別：play＝魔法・起動、trigger＝任意誘発、forceTrigger＝強制誘発、eternal、explain）
- `誘発効果設定,ID,タイミング`（場に出た時・エンドフェイズ開始時・メインフェイズ開始時・onAttack（攻撃時）・onOtherSummon・死亡時 など）
- `効果条件設定,ID,条件式`（例：`トリガー受動カード,==,自分`、`トリガー能動カード.所属,!=,自分所属`、`Now自分ターン,==,true`）
- `効果ターゲット設定,ID,選択|ランダム|全体,範囲,枚数`（例：`相手モンスター.?性別:男`、サーチは `ランダム,自分デッキ.?isモンスター:true,1`）
- `@効果` は `switch,効果ID` → `case,1 { … }`。自壊は `効果破壊,自分`。サーチは `効果サーチ,効果対象,自分所属`。
- 魔法・罠の話者は `話者変更,自分プレイヤー`（敵マスターの声）。
- **倒されたモンスターを蘇らせる（N11の分裂。未検証）**：`効果設定,3,forceTrigger,…` ＋ `誘発効果設定,3,死亡時` ＋ `効果場所設定,3,墓地ゾーン`、`case,3` で `蘇生,自分,自分所属`。公式ドキュメントでは、墓地で動く誘発は強制誘発のみ。`蘇生` は新しいカードとして作り直されるため、そのカードの変数は引き継がれない → 1回きりのフラグは `自分プレイヤー.$〜` に持たせる。

## 6. 画像生成（MOD画像一括生成ツール）

### 6-1. 使い方
```
run_mod.bat <コード> all                         ← 全51枚
run_mod.bat <コード> <キー> --random --batch 4   ← 1枚を候補4枚で撮り直し
install_images.bat <コード> "<ゲーム>\Picture"   ← 出力をゲームに正しい名前で入れる
```
- ツールの場所：ユーザーのPCの `Downloads\tools`。ComfyUIは `Downloads\ComfyUI_windows_portable`（起動は `run_nvidia_gpu.bat`、出力は `ComfyUI\output`）。
- ComfyUIは保存名の末尾に `_00001_` を付ける。**install_images.bat で番号を外して `Picture/<コード>/` にコピーしないと、カードが画像を見つけられず処理が止まる。** 同じキーは一番新しいものが入る（立ち絵は背景除去版 `_rmbg` を優先）。
- **ダブルクリック用の `gen_<コード>_all.bat`**（N2で作成）：ComfyUIが起動していなければ起動し、準備ができるのを待ってから全枚数を投入する。コマンドを打たずに生成できる。
- 1MOD 51枚：立ち絵5・技CG7・敗北28・オナニー5・魔法5・背景1（`<コード>_bg.png`。N1は `Host_room`、N7は `Inmon_shrine`）。カードで命乞いCG（`inochigoi`）・おねだりCG（`onedari`）を使うMODは、その分も生成対象に入れる（N2・N6）。
- `run_mod_batch.py` はComfyUIのキューに送るだけで、すぐ終わる。できあがるのはキューが進んでから（1枚20秒ほど）。**複数のMODを同時に投げると同じキューに並ぶ**（順番に処理されるだけで問題はない）。
- **同じプロンプト・同じシードをもう一度投げると、ComfyUIはキャッシュを使って新しいファイルを保存しない**。撮り直しは必ずシードを変える（`--random`）。
- **もう1つの方式：MODごとの単独バッチ**（N5・N8・N11・N15）：`N<番号>_<コード>_画像生成バッチ` フォルダに `comfy_batch.py`・`config.json`・`<コード>_prompts.json`・`run_<コード>.bat`・`install_<コード>.bat` をまとめたもの。`scene_overrides.py` を書き換えずに済み、ゲームで使う名前のまま `output\<コード>\` に保存する（番号の付け外しは不要）。設定はN8と同じ（Animaの3ローダー＝`waiANIMA_v10Base10` ＋ `qwen_3_06b_base` ＋ `qwen_image_vae`、832×1216、er_sde・simple、36step、CFG4.5）。撮り直しは `--random --batch 4` → `--pick <キー> <番号>`。

### 6-2. シナリオ完成後のCG
- 書き上げたMODは `scene_overrides.py` に場面ごとの定義を追加する（部屋・道具・構図）。未作成のMODは企画書から自動で組み立てる。
- 場面は具体的な構図（誰が・どこで・どの体勢で・何を）で書く。膝に乗せる構図は脚が混ざるので「背もたれ越しに後ろから」にする。
- シナリオから場面を拾うときは、敗北ルートごとに「一番象徴的な場面（多くは絶頂の場面）」を1つ選ぶ。同じ責め手の3〜4ルートが同じ構図になりそうなら、道具や場面を変えて描き分ける（N2のシズク：椅子の前でキス／砂時計／鍵のネックレス／机に伏せてアナルパール）。
  - N11では各ルートの「結末の印」（首の青い輪、胸の三重の紫の輪など）を画像に入れて描き分けた。
  - N6では各ルートのシナリオの部屋（糸の天蓋・衣装部屋・人形劇場・オルゴールの間・完成の間 など15部屋）をそのまま `PUPPET_PLACE` にした（`claude/N6_Puppet_ComfyUI_Prompts.md`）。
- `python apply_scene_overrides.py <コード>` で、そのMODだけプロンプトを作り直せる（N2で追加）。
- **`scene_overrides.py` と `apply_scene_overrides.py` は複数の作業が同時に書き換える**。書き換える前に必ずPCの最新版を取り込み直し、自分のMODの部分だけ差し込んでから戻す。古い版で上書きすると、ほかのMODの定義が消える（N2の作業で一度起きた。すぐ戻した）。
- 生成したら**必ず全枚数を目で確認**し、崩れた分だけ撮り直す（一覧画像にまとめて見ると早い）。

## 12. ドキュメント間の矛盾点の整理（2026-09-23・注記のみ／削除なし）

過去の資料（`Project_Instructions.md`／`Project_Instructions_追記.md`／`Project_Knowledge.md`／`MOD企画書_15種_v2.md`）とこのまとめ.mdの間で見つかった食い違いを記録する。**各資料の本文は残したまま、ここに正しい扱いを注記する方針**（削除は最小限）。

1. **モンスターが力尽きた時の扱い（メス奴隷化 vs 破壊）**
   プロジェクトの最上位カスタム指示には「一定数累積されるとモンスターの場合は破壊される」とあるが、これは一般論としての説明。**実際の扱いはMODのシナリオに応じて選んでよい**（固定ルールにしない）。既存の実績（ロゼッタMOD・N1・N7）はすべて「敵フィールドに『メス奴隷（奴隷）』として特殊召喚（寝返り）」方式。新しいMODで「破壊して退場させる」方が世界観に合う場合はそちらを使ってよいが、その場合は該当MODの設計メモ（本書8章相当の完成MODメモ）に明記すること。
   **追記（2026-09-23）**：3つ目の扱いとして「女装娘」（女装化系の技・魔法を受けたら即、破壊扱い→主人公側に女装娘として特殊召喚）が加わった（1章）。

2. **累積スタックの対象技数**
   最上位指示の原案は「攻撃タイプ2種のうち1種だけが累積スタック」だったが、実装テンプレート（4章）では技1〜3のすべてが共通の `自分プレイヤー.$ゲージ` に加算される方式で統一されている。**今後もこの「全技が共通ゲージに加算」方式を正とする**（1種のみ累積、という原案は採用しない）。
   > 【復元メモ】2026-09-24 の企画書v4で「★得意技だけがスタックを積む・受けた側が個別に持つ（主人公12／モンスター6）」に改められた。v4を正とする。

3. **ゲージ上限・変換しきい値の版差**
   - ロゼッタMOD（黒薔薇の館）：メス堕ち度0〜20、メス奴隷への変換しきい値13。**これは過去の完成品専用の値**（`Project_Knowledge.md` に記載）。
   - N1〜N15シリーズ：ゲージ0〜24、変換しきい値8（`MOD企画書_15種_v2.md` §1-3）。**今後のMODはすべてこちらに統一**。
   ロゼッタMODの値を新MODに流用しない。

4. **「ターン終了時にゲージ−1」の表記**
