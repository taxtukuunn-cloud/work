# N18 ラミアの神殿（コード Lamia）共通仕様 ― 執筆者向け

登場人物は全員20歳以上の成人。個人利用のみ。完全M向け（責め手上位・逆転なし・主人公は常に受け身・主人公は挿入しない・主人公は責め手に触れて責めない）。
暴力・流血・凌辱・アヘ顔はなし。丸呑み・捕食の描写もしない。「甘く、ゆっくり、巻き付かれて逃げ道がなくなる」支配。責め手は衣装を着たまま責める（責めに必要な所だけ薄衣をずらす）。

## 世界観
砂漠の遺跡の奥にある「蛇神の神殿」。砂岩の柱と蛇の彫刻、昼でもひんやりした石の回廊、奥へ進むほど香油と乾いた砂の匂いが濃くなる。
下半身が大蛇のラミアたちが棲み、迷い込んだ男を「贄」として迎える。ラミアは体温が低く、人の体温を好む。温かい獲物に巻き付き、長く先割れした舌で乳首と後ろを時間をかけて舐め開き、離さない。
**舌の責めがこのMODの売り**。舌は長く、細く、先が二股に割れ、ひやりとして湿っている。二股の先で左右を同時に、あるいは奥の一点を挟むように舐める。
主人公は二十代の冒険者（カード使いの青年・成人）。身長150cmと小柄で華奢。ラミアたちは全員頭ひとつ以上背が高く、蛇体を含めれば何倍も大きい。常に見下ろされ、とぐろの中にすっぽり収まってしまう体格差。一人称「僕」。
堕ちた後は、神殿の中で「蛇の番（つがい）」として暮らす。

## 敗北シナリオファイルの書式（`scen/Lamia_lose_<経路>_<key>.txt`）
経路：btl（戦闘負け）／onani（オナニー負け）／inochi（命乞い負け）／onedari（おねだり負け）

```

セリフ,（責め手の冒頭セリフ1）
セリフ,（責め手の冒頭セリフ2）

……
説明,（最後の地の文）
主人公攻撃タイプ弱点付与,キス,50
```
- `話者,自分` ＝ そのシナリオの責め手、`話者,相手` ＝ 主人公。
  **それ以外の人物のセリフ（例：モンスターのシナリオに出てくるシェスカ）は `説明` の中に「シェスカが囁く。『……』」の形で書く。**
- 使うコマンドは `画像` `話者` `セリフ` `説明` `主人公攻撃タイプ弱点付与` だけ。
- 画像は冒頭に1回（ファイル名はシナリオと同名の .png）。絶頂の場面の前にもう1回同じ画像を出してよい。
- 1行は `コマンド,本文`。本文は1行につき全角40〜150字程度。長い地の文は `\n`（半角バックスラッシュ＋n）で改行してよい。
- 空行・インデント・コメントは不要。改行コードはLFでよい（後でCRLFに変換する）。

### 本文の禁止事項（厳守）
- **半角カンマ `,` 禁止**（全角「、」）。
- 半角の `$ % & # { } < > ; ! ?` を本文に書かない。全角「！」「？」を使う。ハート「♡」は可、「♪」は不可。
- 弱点付与の攻撃タイプは下のあらすじ表の指定どおり（公式名）。

### 文字数
- **各ファイル、セリフ・説明の本文だけで5,000字以上（目標5,500〜6,500字）**。

### 構成（この順で全部入れる）
1. 冒頭セリフ2行＋画像
2. その経路で負けた経緯の振り返り（カードバトル中の状況に触れる：絡みつき度が上がっていく、仲間の男モンスターが巻き取られた 等）
3. 場所の移動と情景（あらすじ表の場所）
4. 責め手の手法の提示（舌を見せつける、とぐろを作る、瞳を合わせる 等）
5. 段階的な責め（抵抗→崩れる→自分から求める）。絡みつき度の4段階（見つめられる→巻き付かれる→舌が這う→締め上げ）を体で追体験させる
6. 経路特有の「言わせる・選ばせる・差し出させる」場面
7. **絶頂を3回以上**。あらすじ表の「区切り」で意味づけする。ここに一番文字数を使う
8. 責め手の締めのセリフ（あらすじ表の「印」の授与）
9. 後日談（1日目・2日目・3日目…と日常が侵食されていく。日ごとに1段落）
10. 自分から神殿に戻る場面（責め手の出迎えで締める）
11. 最後の行：`主人公攻撃タイプ弱点付与,<指定の攻撃タイプ>,50`

### 経路ごとの軸
- btl（戦闘負け）：舌で奥をほどかれ、巻き付かれたまま達し続ける
- onani（オナニー負け）：自分の指では届かない所を、舌を見せつけられながら思い知らされる。見られる・数えられる恥
- inochi（命乞い負け）：とどめを刺す手が止まった一瞬の情け→「逃げていい」と緩められた胴が、振り向いた瞬間に締まる
- onedari（おねだり負け）：舐めてほしい場所と長さを自分の口で言わされ、それが毎日の決まりになる

### 表現のルール
- 絶頂は「射精」「果てる」「白いものが溢れる」など。露骨な俗語の連発は避け、官能小説の品位で。
- 舌の感触（冷たさ、二股の先、細さ、長さ、ぬめり、奥で折り返す動き）、鱗の感触（なめらか、ひんやり、少しずつ温まる）、締め付けの圧、蛇の瞳の縦長の瞳孔、先割れの舌がちろちろ出入りする音を具体的に。
- 責め手は常に余裕と上位。自慰・受け身・自爆にしない。
- 同じ言い回しの繰り返しで字数を稼がない。

## 戦闘セリフ JSON（`lines/<key>.json`）
シナリオと同じ口調で、カードで使う短いセリフも書く。**本文の禁止事項はシナリオと同じ**（半角カンマ・記号禁止）。1セリフ全角15〜70字。

### モンスター（e1・e2・e3・boss）の形
```json
{
 "techs": [
  {"atk": ["段階1の責め手","段階2","段階3","段階4"], "rx": ["段階1の主人公の反応","段階2","段階3","段階4"]},
  {"atk": [...4], "rx": [...4]}
 ],
 "summon": "召喚時の口上",
 "turnend": "自ターン終了時の効果のセリフ（e3のみ。他は空文字）",
 "destroy": "男モンスター（主人公の仲間）を巣に巻き取って破壊する時のセリフ",
 "onedari_open": "おねだりされた時のセリフ",
 "onedari_opts": ["技1をねだる選択肢の文（主人公視点・15字以内）", "技2をねだる選択肢"],
 "onedari_rx": "主人公のおねだりのセリフ",
 "inochi": ["命乞い1", "命乞い2（情けにつけ込む布石）"],
 "inochi_fail": "とどめを刺された時の一言",
 "inochi_win": ["手が止まった瞬間の責め手1", "責め手2"],
 "inochi_rx": "主人公の反応",
 "onani": [["1回目の責め手1","1回目2"], ["2回目以降1","2回目以降2"]],
 "onani_rx": "主人公の反応",
 "end": "勝利した時の一言",
 "flavor": "カードのフレーバーテキスト（60〜100字）"
}
```
techs の順番は技の表の順（e1：蛇の瞳→舌先、e2：牙の媚毒→尾の先、e3：舌→胴、boss：同時→交わり）。

### マスター（m1・m2・m3）の形
各エージェントは自分の技の分だけ書く：
```json
{
 "atk": [...4], "rx": [...4],
 "onedari_opt": "この技をねだる選択肢の文（15字以内）"
}
```
**m1 の担当は、加えてマスター共通のセリフも書く**（同じファイルに）：
```json
{
 "field_first": ["初めて神殿に来た時の情景（説明）", "シェスカのセリフ1", "セリフ2"],
 "field_won": ["前回主人公が勝った時のセリフ1", "セリフ2"],
 "field_lost": ["前回負けた時のセリフ1（戻ってきたことを喜ぶ）", "セリフ2"],
 "continue": ["前回の続きを選んだ時：情景（説明）", "シェスカのセリフ1", "セリフ2"],
 "start": "試合開始の一言",
 "summon": ["召喚宣言：段階1", "段階2", "段階3", "段階4"],
 "turnend": ["ターン終了時：段階1（魅了）", "段階2（魅了）", "段階3（攻撃不能）", "段階4（攻撃不能）"],
 "onedari_open": "おねだりされた時",
 "onedari_rx": "主人公のおねだりのセリフ",
 "inochi": ["命乞い1", "命乞い2"], "inochi_fail": "...", "inochi_win": ["...", "..."], "inochi_rx": "...",
 "onani": [["1回目1","1回目2"],["2回目以降1","2回目以降2"]], "onani_rx": "...",
 "end": "勝利の一言",
 "destroy": "男モンスターを巻き取る時",
 "flavor": "フレーバー（60〜100字）"
}
```
書いたら `python3 -c "import json;json.load(open('<ファイル>'))"` で JSON として読めることを確認する。
